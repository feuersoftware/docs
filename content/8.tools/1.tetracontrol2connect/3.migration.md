Version 3.0 bringt eine neue webbasierte Admin-Oberfläche und speichert alle Einstellungen in einer SQLite-Datenbank statt in der `appsettings.json`. Der Umstieg ist jedoch einfach: Beim ersten Start von Version 3.x wird die vorhandene `appsettings.json` automatisch erkannt und importiert.

## Was hat sich geändert?

| Bereich | Version 2.x | Version 3.x |
|---------|-------------|-------------|
| Konfiguration | `appsettings.json` (manuell bearbeiten) | Admin-Oberfläche unter `http://localhost:5050` |
| Datenspeicherung | JSON-Datei | SQLite-Datenbank (`settings.db`) |
| Einrichtung | Datei manuell anlegen und bearbeiten | Einrichtungsassistent (über das Dashboard) |
| Datensicherung | Manuelles Kopieren der Datei | Integrierte Sicherungen in der `settings.db` (Bereich „Sicherungen“) |
| API-Schlüssel | Organisations- oder Standort-Schlüssel | **Nur Standort-Schlüssel** (seit 2.8.0) |
| Laufzeitumgebung | .NET 8/9 | .NET 10 |

::warning
**Wichtige Änderung bei API-Schlüsseln (bereits seit Version 2.8.0)**

Seit Version 2.8.0 sind in der Konfiguration ausschließlich **Standort-API-Schlüssel** zulässig. Organisationsschlüssel werden beim Start abgelehnt. Stellen Sie sicher, dass in Ihrer bestehenden Konfiguration nur Standort-Schlüssel verwendet werden, bevor Sie das Upgrade durchführen.
::

## Migrationsschritte

### 1. Vorhandene Konfiguration sichern

Erstellen Sie vor dem Upgrade eine Sicherungskopie Ihrer bestehenden `appsettings.json`:

```
appsettings.json → appsettings.json.bak
```

### 2. .NET 10.0 Runtime installieren

Version 3.x benötigt die **.NET 10.0 Runtime**. Laden Sie diese von [dot.net/download](https://dotnet.microsoft.com/download) herunter und installieren Sie sie.

### 3. Neue Version entpacken

Entpacken Sie das Archiv der neuen Version **in dasselbe Verzeichnis** wie die bisherige Installation. Stellen Sie sicher, dass Ihre bestehende `appsettings.json` im Verzeichnis verbleibt.

### 4. Anwendung starten

Starten Sie die Anwendung. Beim ersten Start:

1. Die Datenbank `settings.db` wird angelegt.
2. Die `appsettings.json` wird automatisch auf bekannte Konfigurationsabschnitte geprüft.
3. Gefundene Einstellungen werden in die Datenbank importiert.
4. Das Dashboard der Admin-Oberfläche öffnet sich unter `http://localhost:5050`.

::warning
Der automatische Import erfolgt nur, wenn die Datenbank noch **keine Einstellungen** enthält. Zur Erkennung muss die `appsettings.json` mindestens einen der Abschnitte `ProgramOptions`, `TetraControlOptions` oder `ConnectOptions` enthalten. Wurde Version 3.x bereits einmal ohne die alte Datei gestartet, hilft ein späteres Hineinkopieren nicht mehr – nutzen Sie dann den manuellen Import (Schritt 6).
::

::note
Der automatische Import erkennt die folgenden Abschnitte in der `appsettings.json`:
- `TetraControlOptions`
- `ProgramOptions`
- `ConnectOptions`
- `StatusOptions`
- `SeverityOptions`
- `SirenCalloutOptions`
- `SirenStatusOptions`
- `PatternOptions`
::

### 5. Konfiguration in der Admin-Oberfläche prüfen

Öffnen Sie `http://localhost:5050` und prüfen Sie alle Einstellungsbereiche, um sicherzustellen, dass der Import vollständig und korrekt war.

### 6. Manueller Import (falls erforderlich)

Sollte der automatische Import nicht stattgefunden haben oder die Konfiguration nachträglich erneut importiert werden müssen:

1. Admin-Oberfläche öffnen und **„Sicherungen“** aufrufen.
2. Unter **„appsettings.json importieren“** die bisherige `appsettings.json` auswählen.
3. Bestätigen und **„Datei importieren“** klicken.
4. TetraControl2Connect **neu starten**, damit alle Dienste die importierten Einstellungen verwenden.

In der Datei enthaltene Einstellungsbereiche werden vollständig ersetzt, nicht enthaltene Bereiche bleiben erhalten. Vor dem Import wird automatisch eine Sicherung angelegt.

Alternativ ist der Import über die REST-API möglich (`POST http://localhost:5050/api/settings/import`). Dabei kann die JSON-Datei als Request-Body übergeben werden. Ohne Body wird die `appsettings.json` aus dem Arbeitsverzeichnis verwendet. Auch hier ist anschließend ein Neustart erforderlich.

## Referenz: appsettings.json Konfigurationsabschnitte

Falls Sie die `appsettings.json` aus der alten Version noch benötigen oder einen manuellen Import vornehmen möchten, finden Sie hier den Aufbau der wichtigsten Abschnitte. Die Beispielwerte für Status, Schweregrade und Sirenencodes entsprechen den Hessen-Standardwerten, die auch bei einer Neuinstallation gesetzt werden.

## Häufige Fragen

**Muss ich die `appsettings.json` nach dem Upgrade löschen?**

Nein. Die Datei wird nach dem Import nicht gelöscht und schadet dem Betrieb nicht. Sie kann aber nach erfolgreicher Migration entfernt werden.

**Was passiert, wenn ich die Version 3.x ohne eine bestehende `appsettings.json` installiere?**

Die Anwendung startet mit den Standardwerten (Hessen-Standards für Status, Schweregrade und Sirenencodes). Auf dem Dashboard erscheint die Karte „Ersteinrichtung erforderlich“; über „Einrichtung starten“ führt der Einrichtungsassistent durch die Erstkonfiguration. Fehler-Übersetzungen für die Sirenenüberwachung sind bei einer Neuinstallation nicht hinterlegt.

**Kann ich die Einstellungen zwischen Installationen übertragen?**

Ja, indem Sie die Datei `settings.db` auf die andere Installation kopieren. Die integrierten Sicherungen liegen in der `settings.db` selbst und können nicht als separate Datei exportiert werden. Alternativ kann auf der neuen Installation eine `appsettings.json` über „Sicherungen → appsettings.json importieren“ eingelesen werden.

**Kann ich die Konfiguration weiterhin als JSON-Datei exportieren?**

Die aktuelle Version unterstützt keinen direkten JSON-Export der Einstellungen. Alle Einstellungen sind jedoch über die REST-API unter `http://localhost:5050/api/settings` abrufbar und können von dort extrahiert werden.
