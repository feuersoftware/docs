# Sirenenüberwachung (BETA)

TetraControl2Connect kann Steuercode-Rückmeldungen von Sirenen auswerten, die über Datenfunkgeräte per SDS- oder Statusnachrichten eingehen. Bei Fehlerzuständen wird automatisch eine **Mängelmeldung** im Connect Portal erstellt.

**Unterstützte Hersteller:** Sirene24 und Sonnenburg

---

## Sonnenburg – Steuercodes

| Code | Beschreibung | Details | Mängelmeldung |
|---|---|---|---|
| E000 | Ausgelöst | Sirene wurde erfolgreich aktiviert | Nein |
| E001 | Nicht ausgelöst | Alarm konnte nicht verarbeitet werden | **Ja** |
| E002 | Besetzt, gespeichert | Besetzt, aber in Warteschlange | Nein |
| E003 | Besetzt, abgelehnt | Besetzt und abgelehnt | **Ja** |
| E004 | Technisch OK | Normalbetrieb | Nein |
| E005 | Technischer Fehler | Nicht verfügbar für Alarme | **Ja** |
| E006 | Vorübergehend deaktiviert | Nicht verfügbar | **Ja** |
| E007 | Sabotagealarm | Türkontakt geöffnet | **Ja** |
| E008 | Netzspannungsfehler | Netzspannungsversorgung ausgefallen | **Ja** |
| E009 | Batteriefehler | Batterieversorgung ausgefallen | **Ja** |
| E00A | Übertemperatur | Überhitzung / Brandzustand | **Ja** |
| E00B | Sabotage beendet | Türkontakt geschlossen | Nein |
| E00C | Netzspannung wiederhergestellt | Netzspannungsversorgung wieder vorhanden | Nein |
| E00D | Batterie wiederhergestellt | Batterieversorgung wieder vorhanden | Nein |
| E00E | Temperatur normalisiert | Übertemperatur-Zustand beendet | Nein |

## Sirene24 – Statuscodes

| Nachricht (Text in der SDS) | Beschreibung | Mängelmeldung |
|---|---|---|
| Fehler bei der Alarmauslösung | Nicht ausgelöst, Sirene hat auf eine Alarmierung nicht ausgelöst | **Ja** |
| STATUS=1 | Technischer Status Fehler, Sirene nicht für Alarmierung verfügbar | **Ja** |
| SPRT Sabotage: geöffnet | Sabotagealarm, Türkontakt geöffnet | **Ja** |
| SPRT Fehler Netz, Batteriebetrieb | Fehler Netzstromversorgung | **Ja** |
| SPRT Batteriespannung niedrig | Fehler Batteriestromversorgung | **Ja** |
| PRT Temperatur zu hoch! | Übertemperatur (Überhitzung, Brand) | **Ja** |
| SPRT Sammelstörung | Sammelstörung, nicht näher bezeichnet | **Ja** |

Die Sirene24-Meldung `STATUS=0` wird als Heartbeat ausgewertet.

## Konfiguration

Die Auswertung wird in der Admin-Oberfläche unter **„Sirenen-Status“** in der Liste **„Fehler-Übersetzungen“** gesteuert (Spalten **„Fehler-Code“** und **„Übersetzung“**, neue Einträge über **„Neuer Fehler-Code“**). Die Sirenen selbst werden unter **„Connect / Standorte“** beim jeweiligen Standort mit ISSI, Sirenenname und optionalem Heartbeat-Intervall angelegt (siehe [Konfiguration](/tools/tetracontrol2connect/konfiguration#sirenen)).

- **Sonnenburg:** Als Fehler-Code wird der Steuercode eingetragen (z. B. `E001`). Er muss dem gemeldeten Statuscode entsprechen.
- **Sirene24:** Als Fehler-Code wird der Text der SDS eingetragen (z. B. `SPRT Sammelstörung`). Ein Eintrag passt, wenn der Meldungstext diesen Text enthält.
- Groß-/Kleinschreibung wird jeweils ignoriert.

**Jeder eingetragene Fehler-Code löst eine Mängelmeldung aus.** Ob eine Meldung zu einer Mängelmeldung führt, hängt also allein davon ab, ob sie in den Fehler-Übersetzungen eingetragen ist. Tragen Sie daher nur die Codes und Texte ein, die eine Mängelmeldung erzeugen sollen. Die Spalte „Mängelmeldung“ in den Tabellen oben zeigt die empfohlene Konfiguration.

::warning
Nach einer **Neuinstallation sind keine Fehler-Übersetzungen hinterlegt**. Solange keine Einträge vorhanden sind, erstellt TetraControl2Connect keine Störungs-Mängelmeldungen.
::

**Vorlage für die Fehler-Übersetzungen:**

| Fehler-Code | Übersetzung |
|---|---|
| `E001` | Nicht ausgelöst, Sirene hat auf eine Alarmierung nicht ausgelöst |
| `E003` | Alarmierung: Besetzt und abgelehnt, Sirene war zum Zeitpunkt der Alarmierung mit einem anderen Auftrag belegt. |
| `E005` | Technischer Status Fehler, Sirene nicht für Alarmierung verfügbar |
| `E006` | Sirene temporär abgeschaltet, Sirene steht nicht für Alarmierungen zur Verfügung |
| `E007` | Sabotagealarm, Türkontakt geöffnet |
| `E008` | Fehler Netzstromversorgung |
| `E009` | Fehler Batteriestromversorgung |
| `E00A` | Übertemperatur (Überhitzung, Brand) |
| `Fehler bei der Alarmauslösung` | Nicht ausgelöst, Sirene hat auf eine Alarmierung nicht ausgelöst |
| `STATUS=1` | Technischer Status Fehler, Sirene nicht für Alarmierung verfügbar |
| `SPRT Sabotage: geöffnet` | Sabotagealarm, Türkontakt geöffnet |
| `SPRT Fehler Netz, Batteriebetrieb` | Fehler Netzstromversorgung |
| `SPRT Batteriespannung niedrig` | Fehler Batteriestromversorgung |
| `PRT Temperatur zu hoch!` | Übertemperatur (Überhitzung, Brand) |
| `SPRT Sammelstörung` | Sammelstörung, nicht näher bezeichnet |

### Mängelmeldungen und Heartbeat

- Mängelmeldungen werden in der Kategorie **„TETRA-Sirenen“** mit hoher Priorität erstellt. Die Kurzbeschreibung lautet `Sirenen-Störung: <Sirenenname> | <Übersetzung>`.
- Dieselbe Störung wird 7 Tage lang nicht erneut gemeldet.
- Ein Heartbeat der Sirene (Sonnenburg `E004`, Sirene24 `STATUS=0`) schließt alle offenen Mängelmeldungen dieser Sirene – allerdings nur, wenn bei der Sirene ein **Heartbeat-Intervall** eingetragen ist. Die Klarmeldungen `E00B`–`E00E` schließen keine Mängelmeldung.
- Bleibt der Heartbeat über das eingetragene Intervall hinaus aus (Prüfung alle 5 Minuten, Toleranz 5 Minuten), wird die Mängelmeldung „Sirene offline oder gestört“ erstellt.

::note
Ein Heartbeat-Intervall von einem Tag muss als `1.00:00:00` eingetragen werden – `24:00:00` wird als 24 Tage interpretiert.
::

## Einrichtung in der Sirene24 ATC2

Damit das Sirenen-Steuergerät (ATC2) Statusmeldungen an das TetraControl2Connect-Datenfunkgerät sendet, muss die **ISSI des Datenfunkgeräts** im ATC2-Webinterface als Empfänger eingetragen werden.

### Webinterface aufrufen

1. Netzwerkschnittstelle des Clients auf eine Adresse im Bereich `192.168.1.x` (Subnetzmaske `255.255.255.0`) konfigurieren
2. Webbrowser öffnen und `192.168.1.12` aufrufen
3. Mit Benutzername und Passwort anmelden (siehe Beipackzettel des Geräts)

### Empfänger eintragen

**Einstellungen → Empfänger**

Hier wird eingetragen, welche ISSI Nachrichten vom ATC2 erhalten soll. Die ISSI des TetraControl2Connect-Datenfunkgeräts muss als Empfänger für Alarm- und/oder Statusmeldungen eingetragen werden.

| Feld | Beschreibung |
|---|---|
| **ISSI** | ISSI des Datenfunkgeräts (TetraControl2Connect) |
| **Status** | Gibt an, ob der Empfänger Statusmeldungen erhält |
| **Alarm** | Gibt an, ob der Empfänger Alarmmeldungen erhält |
| **Intervall** | Optionaler regelmäßiger Statusbericht (`off`, `hour`, `day`, `week`) |

> **Hinweis:** Damit alle relevanten Steuercode-Rückmeldungen übertragen werden, sollte der Empfänger sowohl **Status- als auch Alarmmeldungen** aktiviert haben.

### Absender und Rechte

**Einstellungen → Absender und Rechte**

Falls das Datenfunkgerät auch Statusabfragen oder Steuerbefehle an das ATC2 senden soll, muss seine ISSI hier ebenfalls eingetragen werden:

| Feld | Beschreibung |
|---|---|
| **ISSI** | ISSI des Datenfunkgeräts |
| **Alarmierung** | Darf der Absender einen Alarm auslösen? |
| **Statusabfragen** | Darf der Absender Statusabfragen durchführen? |
| **Programmierung** | Darf der Absender Fernprogrammierungen durchführen? |
